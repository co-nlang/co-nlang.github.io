# meta/first_encounter — 第一次認識 n/ 的人

**起筆**:2026-08-08。
**這是什麼**:官網的**原料**,不是文案,也不是規格。用來想清楚「官網要說什麼、對誰說」,
文案與頁面之後才從這裡編織出來。與 `nlang-spec/meta/oo/` 同一種東西、同一種紀律:
判別承重的方式是「**拿掉它,別的句子會變成假的**」。

〔量〕= 本輪實際跑過的量測。〔讀〕= 讀碼/讀文件得到的。

---

## 0. 八句承重的話

1. 官網的讀者是**第一次認識這個語言的人**,而他心裡的問題不是「這是什麼」,是「**我為什麼不現在關掉分頁**」(§1)。
2. 整個 n/ 可能都在解一個問題:**一個結構,能否不靠外部名稱,而由它自身的關係被辨認、觀測與組合?**(§2)
3. 那句話裡的**三個動詞就是站的骨架**——辨認 / 觀測 / 組合。不是四個平行的維度,是一個問題長出三隻手(§2)。
4. n/ 的哲學命題是**假設,不是結論**。先寫下能說得最清楚的那句話,再去找能撐住它的數學,再去實作、去檢驗(§3)。
5. 因此真正的差異點不是「我們更快/更安全」,是「**你可以看著我們出錯**」——而這有東西可以指(§4)。
6. 30 秒入口是**組合**那一隻:「你的兩個程式可以相加」。這裡的「相加」必須立刻落到
   `&` 的可跑例子,不能讓人誤讀成算術 `+`;它可查、不需背景,而且會自己長出三個後果(§5、§9.6.2)。
7. **CUE 是祖先不是對手**,而這件事已經寫在語料裡了——承認它比防守它強(§6)。
8. 石板的問題**不是內容是位置**:在 landing 上它顯得沒被賺到,在「方法」那一節它是一手史料(§7)。

## 1. 讀者

用戶的定位(2026-08-08):

> 「第一次認識這個語言的人,很可能看的就是官網。平常我在 GitHub 上看到一個有興趣的
> project,也是找 README.md 中的官網或是 showcase 頁面。(除非是工具類的,我才會找 docs。)」

**這一句就決定了資訊架構的取捨:官網不是文件站。** 手冊、教學、API 是另一個網域的事
(`docs.` / `blog.`),它們的讀者是**已經決定要用的人**。

### 1.1 前 30 秒真正在問的三件事

一個寫了十年程式的人看到新語言,預設是懷疑的,而且不會承認自己在問:

1. 這是玩具、研究產物、還是我能用的東西?
2. 它做到了什麼我現在的工具做不到的?
3. 這個宣稱可信,還是又一輪行銷?

### 1.2 「強調哪裡不一樣」有一個陷阱

用戶提的方向是對的(「說明白為什麼這不是又一個程式語言」),但:
**每個語言官網都說自己不一樣,老讀者會自動打折。**

⟹ **差異不能用宣稱的,要用他當場能查的東西。** 這條約束貫穿全篇:
§5 的入口要可跑、§4 的差異要可指、§8 的證據要機器算得出來。

### 1.3 用戶自陳的盲點(承重,不要弄丟)

> 「我自己太熟這個語言,所以反而沒辦法思考『第一次認識這個語言的人』會想要認識什麼。」

⟹ **「這一段對陌生人成不成立」這個判斷不能由作者獨自做。** 本檔存在的一半理由就是
把那個視角固定下來,讓它不依賴誰當天記不記得。

## 2. 那個問題,與它的三個動詞

用戶 2026-08-08(整理舊筆記時的自陳):

> 整個 n/ 很可能都在解一個核心問題:
> **一個結構,能否不靠外部名稱,而由它自身的關係被辨認、觀測與組合?**

三個動詞各自對到一組機制:

| 動詞 | 問的是 | 機制 |
| :--- | :--- | :--- |
| **辨認** | 不靠名字,怎麼知道這是哪一個東西 | CAID、內容定址、物件庫 |
| **觀測** | 不執行,怎麼知道它是什麼 | CbO、惰性收斂、`%effect`、blur、視界 |
| **組合** | 兩個結構相遇會怎樣 | 格、`&`、`⊥` 帶 `%cause` ⟹ 版本控制 ⟹ LADD |

**而數學不是第四隻手,它是這三隻手被檢驗的地方。** 障礙階梯問的正是
「這三件事在什麼時候**做不到**」。

### 2.1 這取代了「四個維度」

四個維度(語言 / 發現協議 / 工具 / 研究)的來歷,用戶說明過:

> 「四個維度是這樣來的,當時其實是問**文章怎麼拆**,套到官網好像也行得通。」

**一篇文章切的是材料**——一個讀者、一條路徑、四個章節。
**一個網站切的是讀者**——很多人從不同地方進來,各要不同東西,沒有人照順序讀。

四個維度是一個合法的材料分割,但拿讀者去對,只有三個對得上,
而「發現協議」對不到任何人——**它是章節被升格成了目的地**。
(它是最深的工作,但「發現協議」是一個讀者**還沒形成的問題**的答案。)

⟹ 三個動詞的切法比較好,因為它**不是四個桶,是一條會自己展開的線**。
「維度」這個詞可能也該退場:維度暗示平行的面。

## 3. 方法:哲學命題是假設,不是結論

這是本輪最重的一段。用戶 2026-08-08:

> 這語言的規格書把哲學放在很特別的位子(這也是其他語言不曾做的)。理由也很特別:
> 多數的設計會說是基於某種工程直覺(或反過來,一開始就是結果導向),但**在還沒找到
> 理論或成功的實作來支撐這個結果之前,能說的最清的往往只是一個哲學性的概念**。
> 這不是要說這專案玩什麼哲學或神秘學把戲,而是**真正的價值反而在驗證或證明這套說詞的過程中展現**。

### 3.1 假設 → 導出(用戶原話,幾乎可以逐字上頁)

| 先寫下的那句話(假設) | 導出並實作出來的東西 |
| :--- | :--- |
| 「我們覺得**衝突不是錯誤,而是一種誠實**」 | `⊥` 帶 `%cause` |
| 「**結果不該只有是與非兩種**」 | 直覺主義邏輯 → 量子化後的**正交模格** |
| 「**沒有執行只有觀測**」 | CbO(call-by-observation) |

> 「有了這些設計之後我們才往下一步想,這樣能導出什麼好的結果,然後去設計,去驗證。
> **這也是為什麼會先講 Yoneda,會先講 Bohrification。**」

⟹ 先講 Yoneda / Bohrification **不是炫學**,是在找**能不能撐住左欄**的那個數學。
這一句要寫進頁面,否則讀者只會看到一堆術語。

### 3.2 為什麼這一節必須存在

沒有這一節,石板與序言就是裝飾;有了它,它們是**一手史料**——
「這是我們在還不知道它對不對之前寫下的東西」。

## 4. 差異點:你可以看著我們出錯

多數語言官網的答案是「更快 / 更安全 / 更好寫」。這個專案可以給的答案是別的:

> **你可以看著我們出錯。**

而它不是修辭,有東西可以指:

- **disc 027 §3** 逐條列出「今天我推翻了自己兩處推論、刪掉一條款、判定一則誤歸因」。
- **`meta/VERSIONING.md` §6.2** 是一則**自己記下的政策違反**,小標就叫「誠實記帳」。
- **`meta/ENGINE_SYNC.md`** 每一弧都寫著代修了什麼、哪支探針**對它所守的實作是瞎的**。
- **官網自己**:footer 的驗證戳記是從**真實引擎跑出來的收據**算的——沒跑閘就不印那一行
  (2026-08-08 落地;`scripts/verify-snippets.mjs` + `src/i18n/verified.json`)。

**有 manifesto 的語言不少,但把「假設 → 導出 → 檢驗 → 被推翻的記錄」攤開的,想不到第二個。**
對懷疑的讀者,這比任何效能數字有用——**會記錄自己錯在哪的人,說對的時候也比較可信。**

### 4.1 這一節與 §3 是同一件事的兩半

§3 說**為什麼**要從哲學命題開始(因為那時候能說清楚的只有那個);
§4 說**憑什麼相信**這不是空話(因為檢驗的過程與失敗都留著)。
兩節分開寫會各自變弱。

## 5. 30 秒入口:組合那一隻手

**「你的兩個程式可以相加。」**

兩個 Python 檔不能相加。兩個 n/ 檔可以,而且那個加法是**定義好的、決定性的、全函數**。

好處:不哲學、不需要背景、**五秒內可以自己驗**。然後它往下長出三個後果,全是同一個性質:

| 因為合併有定義 | 所以 |
| :--- | :--- |
| 設定檔就是程式 | 不需要 YAML + TypeScript + 驗證器三件套 |
| 版本控制可以是語義的 | git 只合併位元組,n/ 合併的是意思 |
| 兩台機器可以合併彼此知道的事 | 那就是 LADD / OODP |

### 5.1 頁面已經有這個內容,框架是錯的

現行 landing 的 demo 區塊那四行**就是**這件事,但標題寫成
「資料、型別、邏輯——同一個東西」。

**那是一個關於本體論的主張;讀者要的版本是「一個運算子取代了你現在用的四個工具」。**
同樣四行,兩種讀法。改的是框不是內容。

### 5.2 它不是主幹

「兩個程式可以相加」只是**組合**那一隻手。它是最好的入口,不是論旨。
論旨是 §2 那個問題。**入口與論旨可以不同,但不能矛盾。**

## 6. CUE:祖先不是對手

懂這行的讀者 60 秒內會問「**這不就是 CUE 嗎**」。

〔量 2026-08-08〕掃過全語料:**CUE 出現在 6 個檔案,而且是當作祖先寫的**——

- `docs/intro.md`:「受 CUE Lang 啟發」
- `docs/discussion/022`:「**CUE 給了格論**(單調收斂的數學形式);Memristor 給了值即狀態的直覺」
- `docs/新程式語言構想討論.md`:用戶自陳設計到一半才發現 CUE,對符號設計的相似「感到非常驚訝」

(Dhall 1 個檔案;Nix / Jsonnet / Pkl **各 0**。)

⟹ **不需要防守,站上去就好**,而且那是真的、有記錄的。答案的形狀:

> n/ 從 CUE 的格開始,然後往**兩個 CUE 刻意不去的方向**走:
> **時間**(歷史、精煉、撤回)與**空間**(內容定址、跨機器)。
> CUE 的 `⊥` 是一個編譯錯誤;n/ 的 `⊥` 是一個帶 `%cause` 的**值**,可以被提交、被觀測、被傳。

**這段目前官網一個字都沒有。** 它是最省力的可信度來源:
一個誠實承認自己站在誰肩膀上的專案,比一個宣稱自己全新的專案可信得多。

## 7. 石板:位置不是內容

用戶 2026-08-08:

> 「Hero 區偏哲學的敘事模式或許能提起興趣,但**石板會立刻讓人覺得開錯了網站**。」

診斷更精確的說法:**石板在 landing 第二屏顯得「沒有被賺到」**——
讀者還沒有任何理由相信這是嚴肅工程,就先讀到三段隱秘學詩句。

**裁定方向:不刪,搬。** 但不是搬去「加入我們」(用戶的第一個想法),而是搬進 **§3「方法」那一節的開頭**——
在一個明說「這是我們在還不知道它對不對之前寫下的東西」的區塊裡,
同一段文字的身分完全變了:**從裝飾變成一手史料。**

## 8. 站的形狀(草案)

```
Hero          一句可查的話(組合那隻手,§5)
  ↓
它是什麼      一個運算子取代四個工具 —— demo 區塊已經有了,換框(§5.1)
  ↓
為什麼        三個動詞:辨認 / 觀測 / 組合 —— 一個問題長出來的(§2)
  ↓
方法          石板在這裡。假設 → 導出 → 檢驗 → 被推翻的記錄(§3、§4、§7)
  ↓
證據          版本、測試數、符合性、誠實閘、將來的 playground(§9.1)
  ↓
加入          治理、RFC、四人委員會
```

**證據那一節的紀律與 footer 同一條:全部從機器算出來,不手寫。**
手寫的數字會過期,而過期的數字比沒有數字傷害更大——`oo v0.2.x` 那個戳記就是判例。

## 9. 掛帳

### 9.1 Playground(用戶提出;最強的證據artefact)

讀者自己打 `25 & @int` 看到 `25`,他就不是在相信你,他是**驗證過了**。
那把「這是真的嗎」整個問題換成一次互動。

〔讀 2026-08-08〕**具體擋路石**:`crates/interpreter` 直接依賴 **`ring`** 與 **`tempfile`**,
兩者對 `wasm32-unknown-unknown` 都不友善。而 playground 只需要 parser + evaluator,
不需要簽章與儲存。

⟹ **前置條件是把求值路徑與密碼學/儲存路徑分開**(feature flag 或拆 crate)。
那是個重構不是個週末,但它**同時**是引擎自己該有的乾淨切面。不急,但要記著。

### 9.2 `nlang-docs` 的現況(用戶:「handbook 也是歷史遺跡」)

〔量 2026-08-08〕

| | |
| :--- | :--- |
| `handbook/` | 11 章(00–10)+ `LEARN_N_IN_Y.md`,共 **807 行**,最後一次動 **2026-05-08** |
| 程式碼區塊 | **33 個**,`oo lint` 標記 **3 個(9%)** |
| **結果宣稱** | **整份只有 4 個 `;; →`** |
| 原始構想 | 用戶:「當初的想像是類似 doc.rust-lang.org/book」 |

**兩個重要的但書:**

1. **lint 乾淨 ≠ 還新鮮。** 反證就在手邊:ONE_PAGER 六個區塊 lint **全乾淨**,
   裡面卻躺著一個死掉的 `/fib 6 → 8`(〔量〕今天實跑得 `_|_`)。
   lint 抓的是未定義的名字與圖性質,**不是過時**。
2. **手冊幾乎不主張。** 只有 4 個結果宣稱 ⟹ 誠實閘在它上面沒什麼可檢查的。
   **手冊解釋,ONE_PAGER 示範。**

### 9.3 `/inc` 的來歷 —— 兩種壞法,不要混為一談

〔量 2026-08-08〕ONE_PAGER §4 的原文是**對的,而且今天實跑仍然是 `11`**:

```nlang
/double: x -> x * 2
/increment: x -> x + 1
result: 5 |> /double |> /increment
;; → 11
```

做卡片時 `/increment` 被縮成 `/inc`、定義行被刪、`result:` 綁定被刪,**而 `→ 11` 留著**。

> **兩種壞法:世界動了而文件沒動(`/fib`)、原文是對的而摘要壞了(`/inc`)。**
> 同一台儀器都測得出來,但只有把儀器對準**所有**文件才會發現。

⟹ 官網 README 原本只寫了第一種(drift)。**第二種是壓縮造成的,而官網天生就是在做壓縮。**

### 9.4 詞彙

「維度」可能該退場(§2.1)。**待定,不急著改字**——先把結構定了,名字自然掉出來。

### 9.5 §4 的語料已經存在,而它住在 blog 不住在官網(2026-08-12)

**先修一個位置錯誤**:§4 說差異「有東西可以指」,但它列的四個指向裡有三個
(disc 027 §3、`VERSIONING §6.2`、`ENGINE_SYNC`)**在倉庫深處、中文、寫給我們自己**。
第一次認識 n/ 的人不會去讀一則討論筆記。

但這不是 §4 的缺陷,是**擺錯了樓層**:

| 層 | 放什麼 | 受眾 |
| :--- | :--- | :--- |
| **官網 §4** | 說出**性質**+指路(「被推翻的記錄是公開的,而且跟程式碼同一個倉」) | 第一次來的人 |
| **blog** | 記錄本身,一弧一篇 | 自己走過去的人 |
| **discussion/** | 原料,中文,帶 kill 條件 | 我們 |

⟹ 官網從來就不該展示那份記錄。**這條分工同時是 §10 開放問題 #4 的一半答案**
(官網停在哪裡)。

#### 語料不需要被寫,只需要被 render

〔量 2026-08-12〕`nlang-tools` 的 `top`:

| | |
| :--- | :--- |
| 故事提交 | **79** 則,**一弧一則** |
| 語言 | 英文 |
| 順序 | 時序 |
| **明確帶否定的** | **39 則(49%)** |

(量法:`git log top --format=%s | grep -ci '\bnot\b\|\bno\b\|\bnothing\b\|\bnever\b\|cannot\|\bnor\b'`)

那半數的否定不是文風。「A sentence that describes an intention is not a gate」
「A knob that changes nothing is worse than no knob at all」
「A node newer than you is not a node that has been corrupted」——**每一則都在說「這一弧之前
我們相信的那件事是假的」**。這正是 §4 要的東西,而且已經有 79 個。

為了拓撲紀律(**top 只放故事提交**)採用的規矩,順便產出了整份語料。

〔量〕**故事體是後來長出來的**:最早五則仍是 `v0.2.1: forward-reference resolution — …`
那種技術體。⟹ **blog 的起點在故事體開始處,不在 genesis**;前面那段材料薄。

#### blog 骨架:一弧一篇

> **一弧 = 一篇。標題就是那則故事提交。**

內文三段與弧本身同構,材料全是現成的:

1. **之前我們相信什麼** —— 工單的偵察節
2. **哪個量測推翻它** —— 驗收裡承重的那個數字
3. **代價是什麼** —— 代修 / 破壞性條目 / 新的常設規則

**這解掉「尺度很難拿捏」**:不必決定要挖多深,**弧已經有頭有尾**。
也解掉「不如獨立寫成 blog 文章而不是丟 disc 出來」——骨架是弧,不是筆記。

#### 策展閘(否則 §4 會滑成表演謙虛)

沿用本檔的判別法,套在錯誤上:

> **值得展示的錯誤,是它的修正真的移動了什麼**——改了程式碼、翻了一條裁定、換了一個版號。

`VERSIONING §6.2`(自記的政策違反)、disc 027 §3(推翻自己兩處推論)過得了;拼字勘誤過不了。
沒有這道閘,「你可以看著我們出錯」會變成第二種行銷,而 §1.2 已經說了老讀者對行銷自動打折。

#### 順帶一則印證

CHANGELOG 差的是**狀態**(什麼變了);故事提交差的是**信念**(我們之前以為什麼)。
而 disc 027 的結論正是「**撤回是審計行裡的事實,不是值之間的關係**」——
`top` 就是那條審計行,它每天在做值層做不到的事,樣本 39 個。
(此為 027 的印證,不是新發現;寫在這裡是因為它是 blog 語調的來源。)

#### 9.6.2 「兩個程式可以相加」在現引擎上到底是真的哪一種

**「相加」是入口比喻，運算子不是算術 `+`，是格的 `&`。頁面必須在同一屏說清楚。**

〔量，`oo v0.26.1-627-g715328a+`〕兩個真檔案：

```nlang
;; server.n
server: { host: "127.0.0.1" }
```

```nlang
;; deploy.n
server: { port: 8080 }
```

```text
$ oo run server.n deploy.n --observe server
{
  host: "127.0.0.1"
  port: 8080
}
```

交換檔案順序，輸出逐字相同。這比把兩個值先寫進同一檔更能撐住 Hero 的「兩個程式」。
但它也暴露一個施工前置：現行 `verify-snippets.mjs` 只從 `landing.ts` 抽一個 template string
當一支程式跑，**驗不了兩個來源檔**。Hero 上線前，誠實閘必須先能以同一案例餵多個輸入；
不得退回手寫一張平行測試表。

較穩的 artifact 形狀是：頁面與閘共讀同一組 snippet fixture（兩個 `.n` 來源＋observe＋
expected），UI 只替它加雙語標籤。如此「被 render 的」與「被驗的」仍是同一份東西。

#### 9.6.3 三個動詞不是三個網站入口

現行四張 `dims` 卡做了兩份工作：

1. 解釋 n/ 是什麼；
2. 把人送往 language／discovery／tools／research。

三個動詞只適合第一份工作。它們是同一論旨的三個面，不是三種讀者，也不該各自長成
一個 placeholder 內頁。新的 landing 要明拆兩層：

```text
論旨層：辨認 → 觀測 → 組合
去向層：我想試用 / 讀規格 / 看引擎 / 讀研究 / 看演進記錄 / 參與
```

`discovery` 不再被升格成一種讀者；它回到「辨認如何跨機器」的深入路徑。
`language`／`tools`／`research` 仍可保留為資訊架構，只是不再叫三／四個「維度」。

#### 9.6.4 Hero 的圖可以留，但理由要換成真的

`HeroCanvas` 雖然畫的是 4D tesseract，元件自己的承重說明其實是「你看見的是高維結構的
投影＝觀測」。因此「四個維度」退場不必連圖一起刪；它不是四張內容卡的插圖。

但第一次來的人不會讀 source comment。若保留，文案或無障礙旁註不必解釋 tesseract，
只需讓它服務「同一結構，觀測得到投影」；不能再讓「4D」暗中替舊資訊架構續命。

#### 9.6.5 誠實閘今天有三個洞，不是紅燈但會擋這一弧

〔量 2026-08-20〕本機 `npm run build` 14 頁全綠；`npm run verify:snippets` 為

   但官網正在拿十五個 minor 版以前的引擎替今天背書。**第一實作弧已升至 v0.26.1**，仍採
   bare release，不浮動追 `top`。
2. extractor 盤點時只認屬性名 `code`／`demoCode`。新 schema 若把欄位改叫 `source`，網站可

#### 9.6.6 CUE 段需要降一個聲量，並提高一個精度

〔讀 [CUE Language Specification](https://cuelang.org/docs/reference/spec/)／
[Introduction](https://cuelang.org/docs/introduction/)／
[The Logic of CUE](https://cuelang.org/docs/concept/the-logic-of-cue/)，2026-08-20〕CUE 自己
明文把值放在 lattice、以 `&` 做 commutative／associative／idempotent unification，也明文
支援 multi-source constraint pipelines。故「兩個程式可以相加」**不是對 CUE 的差異點**；
它是 n/ 最誠實的入口，因為這正是祖先留下的門。

可公開的精確說法：

> n/ 從 CUE 已證明有用的格與合一出發，再追問：同一個可合併的值如果還要有耐久身分、
> 歷史、觀測語義，並跨機器交換，會長成什麼？

原 §6 的「CUE **刻意不去**時間／空間」目前只有我們對邊界的理解，沒有 CUE 官方來源證明
「刻意」。公開時應刪掉這個意圖歸因。`⊥` 的差異也應寫成可驗的行為：CUE 官方稱 bottom
「通常表示 error」；n/ 現版可把**帶 ⊥ 欄位的 Combo**固化進歷史並回讀。不要寫成
「CUE 沒有 bottom 值」——兩邊都有 lattice bottom。
